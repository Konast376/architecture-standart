| F5     | Интеграция сайта с кол-центром – заявки с сайта попадают в систему кол-центра, менеджер звонит и предлагает особые условия                    | Система кол-центра (микросервисная, Java) имеет API. Текущий монолит ASP.NET MVC 4.5 не оптимизирован.                                           |
| U2     | Соблюдение системы дизайна банка (брендированные элементы, цвета, шрифты)                                                                     | Нужна централизованная библиотека UI-компонентов. Влияет на фронтенд-архитектуру (React).                                                                                                      |
| U3     | Персонализированные ставки в интернет-банке (с учётом кредитного риска, суммы на счетах)                                                      | Требует сервиса расчёта индивидуальных ставок, обращающегося к кредитному и депозитному бэк-офису. Архитектурно сложно.                                                                        |
| **R**  | Надёжность (Reliability)                                                                                                                      |                                                                                                                                                                                                |
| R1     | Доступность сервисов (24/7) – интернет-банк, сайт, АБС, кол-центр                                                                             | Требует кластеризации, балансировки, мониторинга, автомата переключения. Сейчас интернет-банк работает в одном ЦОД.                                                                            |
| R2     | Отказоустойчивость при аварии ЦОД – переключение на резервный ЦОД без потери данных                                                           | Нужна репликация БД (MS SQL) между ЦОД, синхронизация сессий/кэша, DNS-переключение.                                                                                                           |

Нужен слой очередей (например, Kafka).                                        |
| *R4*   | Идемпотентность обработки заявок – повторная отправка не создаёт дубликат                                                                     | Критично для очередей. Нужен уникальный ID заявки на клиенте и проверка в АБС.                                                                                                                 |

| P2     | Распределение запросов между серверами и ЦОД – балансировщик нагрузки (Nginx/HAProxy)                                                         | Без этого нельзя достичь доступности и производительности. Влияет на сетевую архитектуру.                                                                                                      |
| P3     | Минимизация нагрузки на АБС – асинхронная обработка через очереди, кэширование справочников                                                   | АСР №1. Ввести шлюз/адаптер перед АБС, ставить заявки в очередь.                                                                                                                               |
| *P4*   | Кэширование ставок и справочников (список депозитов, общие ставки) с TTL                                                                      | Использовать Redis или in-memory кэш на уровне интернет-банка для снижения нагрузки на АБС.                                                                                                    |
| **S**  | Поддерживаемость (Supportability)                                                                                                             |                                                                                                                                                                                                |
| S1     | Возможность доработок силами команды банка – использовать технологии с существующей экспертизой (.NET, Java, Oracle, MS SQL)                  | Новый функционал лучше в отдельном микросервисе (Java Spring Boot) или расширениях АБС на PL/SQL. Не менять ядро интернет-банка.                                                               |
| S2     | Совместимость с существующими платформами – новые технологии должны работать с текущими версиями (.NET 4.5, Oracle/PostgreSQL)                | Kafka несовместима с платформой интернет-банка. Возможно, RabbitMQ, MSMQ или таблицы-очереди в БД.                                                                                             |

| S4     | Перспектива перехода на микросервисную архитектуру в части депозитов – выделить функционал в отдельный микросервис                            | Интеграция с интернет-банком через REST API, что снизит связность и упростит развитие.                                                                                                         |
| *S5*   | Версионирование API между интернет-банком/сайтом и новыми сервисами                                                                           | Чтобы изменения не ломали старых клиентов. Важно для постепенного перехода.                                                                                                                    |
