### Нефункциональные требования

|  **№**   | **Требование**                                                                                                                                   |
|:----:|:---------------------------------------------------------------------------------------------------------------------------------------------|
| **NFR1** | Актуальность ставок для кол-центров – не более 30 минут (максимальная задержка между изменением в АБС и доступом для операторов / партнёра). |
| **NFR2** | Доступность API ставок для системы кол-центра – 99,9% (как и у самого депозитного шлюза).                                                    |
| **NFR3** | Файл на SFTP должен быть доступен для скачивания партнёром 24/7.                                                                             |
| **NFR4** | Передача файла должна быть защищена (SFTP с аутентификацией по ключам + шифрование TLS).                                                     |
| **NFR5** | Выгрузка файла не должна создавать существенную нагрузку на АБС или Redis – все ставки берутся из кэша шлюза.                                |

## 3. Решение

## Контекст (Context)
Банк «Стандарт» внедряет MVP по открытию депозитов онлайн. Большинство клиентов — пожилые люди, которые при запуске маркетинговой кампании начнут активно звонить в кол-центр для уточнения ставок.
- Собственный кол-центр работает на системе подрядчика (микросервисы, Java, PostgreSQL).
- Партнёрский кол-центр — внешний, поддерживает только файловый обмен (SFTP).
- Ставки по депозитам в настоящее время хранятся в Excel-файлах, переносятся в АБС вручную.
- Требуется обеспечить операторов обоих кол-центров актуальной информацией о ставках без перегрузки АБС.

## Причина (Facing)
- Операторы кол-центра не видят текущих ставок, что ведёт к неполным консультациям и повторным звонкам.
- Партнёрский кол-центр не может получать ставки через API — только через файлы.
- Прямой доступ к АБС (Oracle) невозможен из-за перегруженности БД и требований безопасности.
- Актуальность ставок должна быть не хуже 30 минут для корректного консультирования.

## Принято (We decided for)
**Создать единый источник ставок в депозитном шлюзе (Java Spring Boot) с кэшем в Redis и предоставить два канала доступа:**
1. **REST API** (JSON) для системы собственного кол-центра — операторы получают ставки через интерфейс системы.
2. **Автоматическую выгрузку CSV-файла на SFTP-сервер** каждые 30 минут — партнёрский кол-центр забирает файл по расписанию.

**Аргументация:**
- Использование существующего депозитного шлюза (по ADR-001) — не требуется новая система.
- Redis уже применяется для кэширования ставок, что исключает лишние вызовы АБС.
- SFTP — стандартный, безопасный протокол, поддерживаемый любым внешним кол-центром.
- Выгрузка раз в 30 минут — компромисс между актуальностью и нагрузкой.

## Отклонено (Neglected)
| **Альтернатива** | **Причина отклонения** |
|--------------|---------------------|
| Прямой доступ системы кол-центра к БД АБС | Высокая нагрузка на Oracle, нарушение разграничения прав доступа. |
| Отправка ставок на e-mail партнёру | Неавтоматизированно, небезопасно, не гарантирует актуальность. |
| Использование API для партнёра | Партнёр технически не поддерживает API. |
| Ручная выгрузка из Excel | Риск ошибок, низкая актуальность, не подходит для масштаба. |

## Чтобы достичь (To achieve)
- Операторы собственного кол-центра видят ставки в реальном времени (задержка < 1 с).
- Партнёрский кол-центр получает файл каждые 30 минут → консультации по актуальным данным.
- Нагрузка на АБС не возрастает — ставки читаются из Redis.
- Автоматизация исключает ручной труд.
- Выполнены нефункциональные требования (актуальность, доступность, безопасность).

## Принимая что (Accepting that)
- Задержка до 30 минут для партнёрского кол-центра — допустимый компромисс для MVP.
- SFTP-сервер становится единой точкой отказа (смягчается резервированием).
- Требуется доработка депозитного шлюза (планировщик, SFTP-клиент, REST endpoint).
- Система кол-центра банка должна быть доработана подрядчиком для вызова API.
- Хранение ключей SFTP требует дополнительных мер безопасности.
- При росте числа ставок объём CSV-файла может увеличиться — предусмотрено сжатие.
